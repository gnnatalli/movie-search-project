# 🎬 Movie Search Project

Итоговый проект по курсам **Python** и **Databases**.

Приложение предназначено для поиска фильмов в базе данных **MySQL Sakila** и сбора статистики поисковых запросов в **MongoDB**.

Проект имеет две версии интерфейса:

- консольное приложение;
- веб-интерфейс на FastAPI.

---

## 🔎 Как работает программа

Пользователь может работать с приложением двумя способами:

- через консольное меню;
- через веб-интерфейс в браузере.

При поиске фильма запрос сначала обрабатывается приложением, после чего данные о фильмах запрашиваются из базы **MySQL Sakila**.

Результаты выводятся пользователю по **10 фильмов на страницу**.

Каждый новый реальный поисковый запрос сохраняется в **MongoDB**.

На основе сохранённых данных формируется статистика:

- 5 последних уникальных запросов;
- 5 самых популярных запросов.

Переход между страницами результатов не считается новым поиском и повторно в статистику не записывается.

### Общая схема работы приложения

```text
Пользователь
     ↓
main.py / web_app.py
     ↓
mysql_connector.py
     ↓
MySQL Sakila
     ↓
Результаты поиска
```

Одновременно при новом реальном поиске:

```text
Поисковый запрос
     ↓
log_writer.py
     ↓
MongoDB
     ↓
log_stats.py
     ↓
Статистика
```

## ⚙️ Как реализован проект

Проект разделён на отдельные модули, каждый из которых отвечает за свою задачу.

- `main.py` — консольный интерфейс;
- `web_app.py` — веб-интерфейс на FastAPI;
- `mysql_connector.py` — SQL-запросы и работа с MySQL;
- `log_writer.py` — сохранение поисковых запросов в MongoDB;
- `log_stats.py` — получение статистики из MongoDB;
- `output_formatter.py` — форматирование результатов и статистики для консольного интерфейса;
- `templates/` — HTML-шаблоны;
- `static/` — стили и изображения;
- `tests/` — автоматические тесты.

Консольная и веб-версии используют общие функции работы с базами данных.

Это позволяет избежать дублирования кода и разделить ответственность между отдельными модулями.

## 📌 Что реализовано

### 1. Поиск по названию

Пользователь может ввести слово или часть названия фильма.

Поиск выполняется по всему тексту названия, а не только по его началу.

Например:

```text
dino
```

может найти фильм, в названии которого это слово находится:

- в начале;
- в середине;
- в конце.

Для этого используется поиск с шаблоном:

```text
%dino%
```

Дополнительно реализована обработка пользовательского ввода:

- удаление пробелов по краям с помощью `strip()`;
- приведение ключевого слова к нижнему регистру;
- проверка пустого запроса;
- регистронезависимый поиск.

Поэтому запросы:

```text
DINO
Dino
dino
   dino
```

обрабатываются одинаково.

---

### 2. Поиск по жанру и диапазону годов

Перед поиском приложение получает из MySQL:

- список всех жанров;
- минимальный год выпуска фильма;
- максимальный год выпуска фильма.

Пользователь может выполнить поиск по жанру и диапазону годов.

Например:

```text
Comedy
2000–2006
```

Также можно указать один конкретный год:

```text
2006–2006
```

В веб-интерфейсе дополнительно доступны:

- 🎬 **Все фильмы**
- ✨ **Фильмы последнего года**
- поиск по годам без ограничения по жанру.

## 📄 Пагинация

На одной странице пользователю отображается максимум **10 фильмов**.

Для определения наличия следующей страницы приложение получает 11 записей:

- первые 10 показываются пользователю;
- наличие 11-й записи означает, что существует следующая страница.

Для перехода между страницами используется `OFFSET`.

Например:

```text
Первая страница  → OFFSET 0
Вторая страница → OFFSET 10
Третья страница → OFFSET 20
```

Служебные запросы при пагинации повторно в MongoDB не записываются.

Таким образом, переход между страницами не увеличивает статистику поисков.

## 📊 Сохранение поисковых запросов

Каждый новый реальный поиск сохраняется в **MongoDB**.

Документ содержит:

```json
{
    "timestamp": "...",
    "search_type": "keyword",
    "params": {
        "keyword": "dino"
    },
    "results_count": 3
}
```

Для поиска по жанру и диапазону годов используется тип:

```text
genre__years_range
```

Пример:

```json
{
    "timestamp": "...",
    "search_type": "genre__years_range",
    "params": {
        "genre": "Comedy",
        "years_range": "2000-2006"
    },
    "results_count": 15
}
```

`results_count` содержит **общее количество найденных фильмов**, а не только количество фильмов на текущей странице.

## 📈 Статистика поисковых запросов

Реализовано два вида статистики.

### Последние запросы

Отображаются **5 последних уникальных поисковых запросов** от новых к старым.

Если пользователь несколько раз выполняет одинаковый запрос, в списке последних уникальных запросов он отображается только один раз — с датой последнего выполнения.

---

### Популярные запросы

Отображаются **5 наиболее часто выполняемых запросов**.

Для каждого запроса показываются:

- параметры поиска;
- количество выполнений;
- общее количество найденных фильмов;
- время последнего выполнения.

Например, если пользователь три раза ищет:

```text
dino
```

в популярных запросах количество выполнений увеличивается, но в последних уникальных запросах `dino` остаётся одной строкой.

## 💡 Сложности и их решения

### 1. Дублирование фильмов

При объединении таблиц MySQL один фильм мог появляться несколько раз, если был связан с несколькими жанрами.

Для решения были использованы:

```sql
GROUP_CONCAT(DISTINCT ...)
```

и:

```sql
GROUP BY
```

В результате один фильм отображается один раз, а несколько его жанров объединяются в одну строку.

---

### 2. Общее количество результатов и пагинация

На странице отображается максимум 10 фильмов.

Однако по требованиям задания в MongoDB необходимо сохранять **общее количество найденных результатов**.

Поэтому поиск фильмов и подсчёт общего количества результатов разделены на отдельные функции.

Например:

```text
На странице: 10 фильмов
Всего найдено: 47
results_count: 47
```

---

### 3. Пагинация и статистика

Переход на следующую страницу не является новым поиском пользователя.

Если бы каждый переход записывался в MongoDB, популярность запроса искусственно увеличивалась бы.

Поэтому в MongoDB записывается только первоначальный реальный поисковый запрос.

---

### 4. Последние уникальные запросы

По заданию необходимо отображать не просто последние 5 документов MongoDB, а **5 последних уникальных запросов**.

Для этого используется MongoDB Aggregation Pipeline с:

```text
$setWindowFields
$rank
```

Это позволяет объединить одинаковые запросы и оставить последнее выполнение каждого из них.

---

### 5. Фильмы с несколькими жанрами

Один фильм может иметь несколько связанных категорий.

Использование обычного `JOIN` приводило к появлению нескольких строк одного фильма.

Для решения жанры объединяются через:

```sql
GROUP_CONCAT(DISTINCT c.name ...)
```

---

### 6. Фильмы без жанра

Для получения фильма даже при отсутствии связанного жанра используется:

```sql
LEFT JOIN
```

А отсутствующее значение заменяется с помощью:

```sql
COALESCE
```

на:

```text
Без жанра
```
