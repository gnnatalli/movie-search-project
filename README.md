# 🎬 Movie Search Project

Итоговый проект по курсам **Python** и **Databases**.

## 📌 О проекте

**Movie Search Project** — приложение для поиска фильмов в базе данных **MySQL Sakila**.

Пользователь может:

- искать фильмы по ключевому слову в названии;
- искать фильмы по жанру и диапазону годов;
- просматривать результаты постранично;
- открывать подробную информацию о фильме;
- просматривать статистику поисковых запросов.

История реальных поисковых запросов сохраняется в **MongoDB**.

На основе этих данных приложение показывает:

- 5 последних уникальных запросов;
- 5 самых популярных запросов.

Проект имеет две версии интерфейса:

- консольную;
- веб-интерфейс на **FastAPI**.

---

# 🔎 Как работает программа

Пользователь может работать с приложением через консоль или через веб-интерфейс.

При выполнении поиска:

1. Пользователь вводит параметры поиска.
2. Программа проверяет и обрабатывает введённые данные.
3. Выполняется SQL-запрос к **MySQL Sakila**.
4. MySQL возвращает найденные фильмы.
5. Пользователю показывается максимум 10 фильмов на одной странице.
6. Реальный поисковый запрос сохраняется в **MongoDB**.
7. На основе сохранённых запросов формируется статистика.

Общая схема:

```text
Пользователь
     ↓
main.py / web_app.py
     ↓
mysql_connector.py
     ↓
MySQL Sakila
     ↓
Результаты поиска
```

При новом реальном поиске:

```text
Поисковый запрос
     ↓
log_writer.py
     ↓
MongoDB
     ↓
log_stats.py
     ↓
Статистика
```

Таким образом:

- **MySQL** используется для получения информации о фильмах;
- **MongoDB** используется для хранения истории поисковых запросов и построения статистики.

# ⚙️ Как реализован проект

Проект разделён на отдельные модули.

Каждый модуль отвечает за свою задачу:

- `main.py` — консольная версия приложения;
- `web_app.py` — веб-версия на FastAPI;
- `mysql_connector.py` — подключение к MySQL и SQL-запросы;
- `log_writer.py` — сохранение поисковых запросов в MongoDB;
- `log_stats.py` — получение статистики из MongoDB;
- `output_formatter.py` — форматирование результатов и статистики для консоли;
- `templates/` — HTML-шаблоны;
- `static/` — CSS и изображения;
- `tests/` — автоматические тесты.

Консольная и веб-версии используют общие функции работы с MySQL и MongoDB.

Это позволяет:

- не дублировать SQL-запросы;
- не дублировать логику статистики;
- разделить ответственность между модулями;
- сделать код более понятным и поддерживаемым.

# ✅ Что реализовано

## 1. Поиск по ключевому слову

Пользователь может ввести слово или часть названия фильма.

Поиск выполняется **по всему тексту названия**, а не только по его началу.

Например:

```text
dino
```

Для поиска используется шаблон:

```text
%dino%
```

Поэтому слово может находиться:

- в начале названия;
- в середине;
- в конце.

Для регистронезависимого поиска используется:

```sql
LOWER(title)
```

Пользовательский ввод также нормализуется.

Например:

```text
DINO
Dino
dino
```

обрабатываются одинаково.

---

## 2. Обработка пробелов и пустого запроса

Перед поиском используется:

```python
strip()
```

Поэтому запрос:

```text
   dino
```

обрабатывается как:

```text
dino
```

Если пользователь введёт только пробелы, после `strip()` получится пустая строка.

В этом случае программа предупреждает пользователя, что ключевое слово не может быть пустым.

---

## 3. Поиск по жанру и диапазону годов

Перед поиском приложение получает из MySQL:

- список всех жанров;
- минимальный год выпуска фильма;
- максимальный год выпуска фильма.

Пользователь может выбрать жанр и указать диапазон:

```text
Comedy
2000–2006
```

Также можно искать по одному конкретному году:

```text
2006–2006
```

В веб-интерфейсе дополнительно реализованы:

- 🎬 **Все фильмы**
- ✨ **Фильмы последнего года**
- поиск по годам без ограничения по жанру.

# 📄 Пагинация

На одной странице отображается максимум **10 фильмов**.

Для определения наличия следующей страницы приложение запрашивает 11 записей.

Логика:

```text
получили 11 записей
        ↓
10 показываем пользователю
        ↓
11-я запись означает, что есть следующая страница
```

Для перехода между страницами используется `OFFSET`.

Например:

```text
Страница 1 → OFFSET 0
Страница 2 → OFFSET 10
Страница 3 → OFFSET 20
```

Важно:

**переход между страницами не считается новым поиском.**

Поэтому служебные запросы пагинации повторно в MongoDB не записываются и не увеличивают статистику популярности.

# 🍃 Сохранение запросов в MongoDB

Каждый новый реальный поисковый запрос сохраняется как отдельный документ.

Пример поиска по ключевому слову:

```json
{
    "timestamp": "...",
    "search_type": "keyword",
    "params": {
        "keyword": "dino"
    },
    "results_count": 3
}
```

Для поиска по жанру и годам используется:

```text
genre__years_range
```

Пример:

```json
{
    "timestamp": "...",
    "search_type": "genre__years_range",
    "params": {
        "genre": "Comedy",
        "years_range": "2000-2006"
    },
    "results_count": 15
}
```

`results_count` — это **общее количество найденных фильмов**, а не количество карточек на текущей странице.

---

# 🔢 Почему используется отдельный COUNT

На странице показывается максимум 10 фильмов.

Например:

```text
Всего найдено: 47
На странице показано: 10
```

Если использовать только:

```python
len(movies)
```

мы получим количество записей текущей страницы.

Но по требованиям проекта в MongoDB необходимо сохранить:

```text
results_count = 47
```

Поэтому поиск и получение общего количества результатов реализованы отдельными функциями.

Например:

```python
search_by_keyword()
```

и:

```python
count_movies_by_keyword()
```

# 📊 Статистика поисковых запросов

Реализовано два вида статистики.

## 5 последних уникальных запросов

Показываются пять последних **уникальных** поисковых запросов от новых к старым.

Если пользователь несколько раз ищет:

```text
dino
```

в списке последних уникальных запросов `dino` отображается только один раз — с датой последнего выполнения.

Для этого используется MongoDB Aggregation Pipeline с:

```text
$setWindowFields
$rank
$match
$sort
$limit
$project
```

---

## 5 популярных запросов

Одинаковые поисковые запросы объединяются.

Для каждого запроса подсчитывается количество его выполнений.

Используются:

```text
$sort
$group
$sum
$first
$limit
```

Например, если пользователь три раза выполнил:

```text
dino
```

в популярных запросах будет:

```text
dino → 3 выполнения
```

Но это по-прежнему будет одна строка.

# 💡 Сложности, с которыми я столкнулась

## 1. Дублирование фильмов после JOIN

Во время разработки я столкнулась с ситуацией, когда один фильм отображался несколько раз.

Причина заключалась в том, что один фильм мог быть связан с несколькими жанрами.

После `JOIN` MySQL возвращал несколько строк одного фильма.

Например:

```text
ACADEMY DINOSAUR | Documentary
ACADEMY DINOSAUR | Family
ACADEMY DINOSAUR | Comedy
```

Для решения использованы:

```sql
GROUP BY
```

и:

```sql
GROUP_CONCAT(DISTINCT c.name ...)
```

Теперь фильм отображается один раз:

```text
ACADEMY DINOSAUR | Comedy, Documentary, Family
```

---

## 2. JOIN и фильм без жанра

Во время разработки обнаружился фильм, который существовал в таблице `film`, но не имел связанного жанра.

Изначально использовался обычный:

```sql
JOIN
```

Из-за этого фильм без записи в `film_category` не попадал в результат, и страница `Подробнее` для него не открывалась.

Для решения был использован:

```sql
LEFT JOIN
```

`LEFT JOIN` сохраняет фильм из основной таблицы `film`, даже если связанной записи с жанром нет.

В таком случае жанр получается:

```text
NULL
```

Чтобы пользователь не видел `NULL`, используется:

```sql
COALESCE
```

который заменяет отсутствующий жанр на:

```text
Без жанра
```

На этом примере я на практике увидела разницу между `JOIN` и `LEFT JOIN`.

---

## 3. Пагинация и статистика

Сначала важно было разделить:

- новый реальный поиск пользователя;
- переход на следующую страницу результатов.

Если каждый переход страницы записывать как новый поиск, статистика популярности станет неправильной.

Поэтому в MongoDB сохраняется только первый реальный запрос.

Переходы между страницами статистику не увеличивают.

---

## 4. Общее количество результатов

По требованиям проекта `results_count` должен содержать общее количество найденных фильмов.

При этом пользователю показывается максимум 10 записей на странице.

Поэтому были созданы отдельные функции `COUNT`, которые получают полное количество результатов независимо от пагинации.

---

## 5. Последние уникальные запросы

Простого получения последних пяти документов из MongoDB было недостаточно.

По заданию нужны именно:

```text
5 последних УНИКАЛЬНЫХ запросов
```

Для решения используется MongoDB Aggregation Pipeline с:

```text
$setWindowFields
$rank
```

Это позволяет выбрать последнее выполнение каждого уникального запроса.

# ⚠️ Надёжность и обработка ошибок

Программа проверяет пользовательский ввод.

Обрабатываются:

- буква вместо числа;
- номер жанра вне допустимого диапазона;
- отрицательное значение;
- год вне допустимого диапазона;
- обратный диапазон годов;
- пустой ключевой запрос;
- строка только из пробелов;
- пробелы до и после ключевого слова.

Например:

```text
2020–2000
```

распознаётся как неправильный диапазон.

Ошибки MongoDB обрабатываются через:

```python
PyMongoError
```
Также в веб-версии реализована обработка системных ошибок MySQL.

Операции обращения к базе данных выполняются внутри `try/except`.
При возникновении `MySQLError` приложение не завершается с traceback,
а показывает пользователю понятное сообщение:

```text
Ошибка подключения к базе данных.
Не удалось выполнить запрос. Попробуйте позже.
